# KYC Validator — Siddhartha Bank KYC + Nepali Citizenship OCR & Cross-Validation

A Streamlit workstation for bank staff processing a **Siddhartha Bank Personal
Account Opening Form (Single/Joint)** alongside a customer's **Nepali
Citizenship Certificate**: upload both, get OCR + checkbox extraction with
editable values, an automatic cross-document identity validation table, and
export. A human reviewer stays in control at every step — nothing here is an
autonomous approval system.

> This application assists with document processing and validation. Final
> verification and KYC decisions must be performed by authorized bank personnel.

## Project overview

Bank KYC intake today looks like: manually read the citizenship certificate,
manually read the KYC form, manually compare every field, manually check
every box, manually recheck everything. This app turns that into: upload →
automatic extraction → automatic comparison → **only the flagged problems get
a human's attention** → export.

It was built against two real supplied documents:

- `Personal_account_opening_form_single-joint.pdf` — Siddhartha Bank's actual
  6-page SBL-PRT-002 form (born-digital PDF, not a scan).
- `download.jpg` — a sample (blank) Nepali Citizenship Certificate template.

The initial ROI configuration for both was generated by **programmatically
inspecting** those documents (word positions + vector-drawn checkbox
geometry for the PDF; Tesseract Nepali OCR + OpenCV border detection for the
citizenship image) rather than hand-typed/guessed coordinates. See
[What's calibrated vs. experimental](#whats-calibrated-vs-experimental) for
exactly which fields that applies to.

## Features

- Multi-page PDF and multi-image upload for both the KYC form and the
  citizenship certificate (front/back or combined PDF).
- Page-by-page preview with rotate, zoom, and ROI overlay.
- Configurable ROI system: 12 field types (`TEXT`, `NUMBER`, `DATE`, `NAME`,
  `ADDRESS`, `CHECKBOX`, `CHECKBOX_GROUP`, `SIGNATURE`, `PHOTO`,
  `THUMBPRINT`, `TABLE`, `OPTION_GROUP`, `CUSTOM`), editable in-app (add /
  edit / delete / duplicate / rename / move / resize) with numeric X/Y/W/H
  fields and a live overlay preview.
- OCR via Tesseract (English / Nepali / mixed), with configurable
  preprocessing per field type (resize, grayscale, denoise, contrast,
  threshold, adaptive threshold, deskew, sharpen).
- Computer-vision checkbox/mark detection (not OCR) — tick, cross, filled
  circle, handwritten mark — with ambiguous marks reported as
  `REVIEW_REQUIRED` rather than guessed.
- Signature / photo / thumbprint **presence** detection only — never
  identity verification.
- Cross-document validation: Nepali↔English name matching (rule-based
  Devanagari transliteration + fuzzy matching, never auto-approved past a
  `PROBABLE_MATCH` threshold), exact/normalized-only ID matching (no fuzzy
  matching on high-risk identifiers), and real BS↔AD date conversion.
- Editable extracted values with OCR confidence shown; re-run validation
  after correction.
- Export to JSON / CSV / Excel.
- Debug Mode for preprocessing traces and detection internals.

## Architecture

```
kyc-validator/
├── app.py                  Streamlit entry point
├── configs/                 JSON document templates (never hardcoded in code)
│   ├── banks/siddhartha/    Siddhartha Bank KYC ROI config + version.json
│   └── citizenship/         Nepali citizenship ROI config
├── document/                 PDF/image ingestion
├── preprocessing/            OpenCV preprocessing pipelines
├── ocr/                       Abstract OCR engine + Tesseract implementation
├── roi/                       ROI schema, CRUD manager, overlay rendering
├── extraction/                Text/checkbox/table/signature extraction
├── validation/                Normalization, matching, BS/AD dates, validator
├── ui/                         Streamlit UI components (one file per section)
├── tools/                      One-off/reusable scripts (see below)
├── tests/                      pytest suite
└── utils/                      Logging (PII-redacting) and small helpers
```

**Design principle:** nothing about "Siddhartha Bank" or "Nepali
citizenship" is hardcoded into the OCR/extraction/validation engines — they
only ever read a `DocumentTemplate` loaded from a JSON config
(`roi/config.py`). Adding NIC Asia, NMB, Global IME, etc. is purely a matter
of creating another `configs/banks/<bank>/*.json` — see
[Adding new banks](#adding-new-banks).

**`tools/inspect_pdf_layout.py`** and **`tools/build_siddhartha_config.py`**
are not demo scaffolding — they're the actual scripts used to generate
`configs/banks/siddhartha/personal_account_opening.json` from the real PDF's
vector layout (word bounding boxes + drawn checkbox-circle geometry). Keep
using this approach for future banks/form revisions instead of hand-typing
coordinates; see [Adding new banks](#adding-new-banks).

## Installation

### Linux setup

```bash
git clone <this-repo>
cd kyc-validator
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### Windows setup

```powershell
git clone <this-repo>
cd kyc-validator
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

### Tesseract installation

Tesseract itself is a system dependency, not a Python package.

**Linux (Debian/Ubuntu):**
```bash
sudo apt-get update
sudo apt-get install -y tesseract-ocr
```

**Windows:** install from the
[UB-Mannheim Tesseract build](https://github.com/UB-Mannheim/tesseract/wiki)
and ensure `tesseract.exe` is on your `PATH` (or set
`pytesseract.pytesseract.tesseract_cmd` explicitly).

**macOS:** `brew install tesseract`

### Nepali Tesseract language installation

**Linux (Debian/Ubuntu):**
```bash
sudo apt-get install -y tesseract-ocr-nep
```

**Windows:** download `nep.traineddata` from the
[tessdata repo](https://github.com/tesseract-ocr/tessdata) and place it in
your Tesseract install's `tessdata` folder.

Verify both language packs are installed:
```bash
tesseract --list-langs
# should list: eng, nep, osd
```

If `nep` is missing, the app will still run — it logs a warning and falls
back to `eng` for Nepali-configured ROIs rather than crashing (see
`ocr/tesseract_engine.py::_resolve_lang`).

## ROI configuration

Open the **Extraction / ROI Editor** tab and switch the sidebar's ROI mode
to **Edit ROIs**. Select a document and page, then:

- Click an existing ROI in the right-hand list to select/highlight it, edit
  its fields, and adjust X/Y/Width/Height numerically with a live preview.
- Use **+ Add ROI** to create a new one.
- ⧉ duplicates, 🗑 deletes. A ⚠ next to an ROI name means it was seeded as a
  placeholder (`"calibrated": false` in the JSON) and hasn't been verified
  against a real coordinate yet.
- If `streamlit-drawable-canvas` is installed, an **Experimental** "draw
  directly on the page" panel is also available (see `requirements.txt`).

ROI edits live in `st.session_state` for the running session. To persist
them, call `roi.config.save_template(template, path)` (wire a "Save
Configuration" button to this in your deployment, or use it from a Python
shell) — kept as an explicit action rather than auto-saving, so an operator
mid-edit can't accidentally overwrite a known-good config.

## Adding new banks

1. Get the bank's form as a **born-digital PDF** if at all possible (a
   flattened scan has no text/vector layer to mine).
2. Run the layout inspector:
   ```bash
   python tools/inspect_pdf_layout.py path/to/new_bank_form.pdf --out layout.json
   ```
   Inspect `layout.json` to see word positions and checkbox geometry per page.
3. Write a `tools/build_<bank>_config.py` modeled on
   `tools/build_siddhartha_config.py` — reuse `find_phrase()` and
   `pair_checkbox_labels()` from `tools/inspect_pdf_layout.py` to anchor
   each field to the form's actual printed labels instead of typing
   coordinates by hand.
4. Save the result to `configs/banks/<bank_name>/<template>.json` (+ a
   `version.json` alongside it, see the Siddhartha one for the shape).
5. It shows up automatically in the sidebar's **Bank** / **Document
   Template** selectors — `roi/config.py::list_bank_templates()` discovers
   banks by directory, nothing else needs to change.

For a scanned (non-digital) form, skip the inspector and build the config by
hand using the in-app ROI editor directly against a rendered page image.

## Adding new documents

The citizenship config (`configs/citizenship/nepal_citizenship.json`) uses
the same `DocumentTemplate` schema as a bank config, just keyed as
`"document_type": "citizenship"`. A second identity-document type (e.g. a
national ID card) would follow the same pattern — add a new JSON file under
`configs/citizenship/` (or a new top-level `configs/<doc_type>/` folder) and
point `app.py`'s second uploader at it.

## Adding new OCR engines

Subclass `ocr.base.OCREngine` (see `ocr/tesseract_engine.py` for the
reference implementation), implement `recognize()` and `is_available()`,
and register it wherever `ocr.tesseract_engine.get_engine()` is currently
called (`extraction/text.py`). No other module talks to Tesseract directly.

## What's calibrated vs. experimental

Per the project's own rule (nothing should look like it works when it
doesn't), here's an honest accounting:

**Calibrated from real inspection (trustworthy starting point, still verify
before production use):**
- All `CHECKBOX_GROUP` ROIs on KYC pages 1–4 and 6 — pixel-exact, matched to
  the PDF's own drawn circle geometry.
- Most page-1 `TEXT`/`NAME`/`DATE` ROIs — anchored to the exact position of
  their printed label, with a heuristic width.
- Citizenship template fields — seeded from Tesseract Nepali OCR + OpenCV
  border detection on the one supplied sample; verify against a few more
  real certificates before trusting it in production, since font
  size/layout can vary between issuing offices.

**Explicitly placeholder / `"calibrated": false` (needs the ROI editor
before use):**
- The Family Details table's per-cell boxes (`family_details_table` on KYC
  page 2) — row positions vary and weren't re-derived automatically; add
  cell ROIs per relation row via the editor.
- Signature / photo / thumbprint boxes on KYC pages 4 and 6 — these are
  marked by a blank box, not a text label, so the label-anchoring approach
  doesn't apply; place them visually in the ROI editor.

**Experimental (works, but don't trust it without a human checking):**
- Photo/thumbprint **presence** detection (`extraction/signatures.py`) —
  tested against the real supplied citizenship template and it read the
  boxed areas as "present" even though they're blank, because that
  template has a busy background watermark pattern running through the
  whole page (visible in `download.jpg`). Variance/ink-based presence
  detection needs recalibration against real scanned certificates, ideally
  ones without as much background texture, before this is reliable.
- Cross-language name matching is rule-based transliteration, not a trained
  model — it works well on the common cases tested (see `tests/`) but will
  degrade on names using less common conjuncts/spellings.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| `TesseractNotFoundError` or OCR results are always empty | Tesseract isn't installed or not on `PATH`. See [Tesseract installation](#tesseract-installation). |
| Nepali OCR returns garbage or empty text | The `nep` language pack isn't installed; the app falls back to `eng` and logs a warning. See [Nepali Tesseract language installation](#nepali-tesseract-language-installation). |
| ROI boxes look shifted after upload | The uploaded page's rendered size doesn't match the template's `native_size`/`reference_image_size`. Re-check the DPI setting, or recalibrate the ROI in the editor for that specific scan. |
| "ROI crop is empty or out of bounds" | The ROI's box falls outside the page after rotation, or the ROI was never given real coordinates (`calibrated: false`) — fix it in the ROI editor. |
| A checkbox that's clearly marked reads as `REVIEW_REQUIRED` | The ink-ratio thresholds in `extraction/checkbox.py` are a starting point tuned for typical scan darkness — adjust `INK_RATIO_CHECKED_MIN`/`INK_RATIO_UNCHECKED_MAX` for your scanner, or raise/lower the ROI's `confidence_threshold`. |
| PDF fails to open | The file may be corrupted or password-protected; the app raises `PDFReadError` with the underlying reason rather than crashing. |

## Privacy

- Processing happens locally: Tesseract runs on-device, and no document or
  extracted field is sent to an external API by default. `.env.example`
  documents (but does not enable) a hook for a future cloud OCR provider —
  if you ever wire one in, surface that explicitly in the UI per this
  project's own design rule.
- `utils/logging.py` redacts known-sensitive field names (citizenship
  number, national ID, PAN, passport number, DOB) before anything is
  logged, and the app never prints raw OCR output to the console.
- Uploaded documents live only in the running Streamlit session's memory
  (`st.session_state`) — nothing is written to disk by the app itself.
  Restarting the app clears everything.
- `.gitignore` excludes any stray `.pdf`/`.jpg`/`.jpeg`/`.png` from being
  committed, so real customer documents used during testing don't
  accidentally end up in version control.

## Limitations

- This is a document-processing aid, not a KYC decisioning system. It does
  not determine whether someone is a PEP, whether an account should be
  opened, or whether identity documents are genuine — it surfaces what's on
  the page and how well two documents agree, for a human to decide on.
- OCR accuracy depends heavily on scan quality; low-resolution or skewed
  scans will produce more `REVIEW_REQUIRED`/low-confidence fields, by
  design — the app is meant to fail toward "ask a human" rather than a
  confident wrong answer.
- Nepali PDFs that embed text using legacy non-Unicode fonts (Preeti,
  Kantipur, etc. — common on older Nepali documents) will not extract as
  readable text via the PDF's text layer; `tools/inspect_pdf_layout.py`
  will pull garbled characters for those portions. This didn't block ROI
  seeding for the Devanagari fields on the supplied form (their English
  counterparts were used to anchor coordinates), but it's worth knowing if
  you inspect a different bank's PDF and see gibberish where Nepali text
  should be — that's a font-encoding issue, not a bug in the inspector.
- The BS↔AD date conversion (`validation/bs_date.py`) depends on the
  `nepali_datetime` package's supported year range; dates outside it come
  back `REVIEW_REQUIRED` rather than a guess, by design.
- See [What's calibrated vs. experimental](#whats-calibrated-vs-experimental)
  for the specific fields/features that need more work before production use.

## Testing

```bash
pytest tests/ -v
```

Covers: normalization/transliteration, name/ID/date/enum matching (including
the spec's own worked example, 2059/04/12 B.S. ↔ 2002/07/28 A.D.), checkbox
mark detection (tick/cross/dot/fill, ambiguous-mark handling, scanner-noise
rejection), and PDF page extraction/error handling. All tests use synthetic
fixtures generated in-test — no real customer or citizenship data is
bundled in this repository.
